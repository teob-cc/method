## One system, carried through all ten steps — and then run again

::: lede
A ticket-booking service, compressed to one line per step, and then **re-derived twelve months later** when a zero-tolerance count refuses to go to zero. The point of the first pass is that each line cites the ones before it and the whole design fits on a page. The point of the second is that the re-run trigger is not decorative — a business KPI drives a model change, and the implementation change simply falls out of the model.
:::

:::
